# 调度器锁机制测试

## 测试文件
- `test_scheduler_lock.py` - 验证文件锁机制的测试脚本

## 运行测试

```bash
cd backend
python3 test_scheduler_lock.py
```

## 测试说明

该测试模拟 3 个 gunicorn worker 进程同时启动，验证只有一个进程能成功获取调度器锁。

### 预期输出

```
============================================================
调度器锁机制测试
============================================================
模拟 3 个 gunicorn worker 进程同时启动
锁文件路径: /home/engine/project/backend/locks/scheduler_test.lock
============================================================

[进程 1] 正在尝试获取调度器锁...
[进程 1] ✓ 成功获取调度器锁！这个进程将运行调度器
[进程 1] 调度器运行中... (1/5)
[进程 2] 正在尝试获取调度器锁...
[进程 2] ✗ 无法获取锁，另一个进程已在运行调度器 (原因: BlockingIOError)
[进程 2] 作为普通工作进程运行...
[进程 3] 正在尝试获取调度器锁...
[进程 3] ✗ 无法获取锁，另一个进程已在运行调度器 (原因: BlockingIOError)
[进程 3] 作为普通工作进程运行...
[进程 1] 调度器运行中... (2/5)
[进程 1] 调度器运行中... (3/5)
[进程 1] 调度器运行中... (4/5)
[进程 1] 调度器运行中... (5/5)
[进程 1] 已释放锁

============================================================
测试完成！
预期结果: 只有一个进程成功获取锁并运行调度器
          其他进程跳过调度器初始化，仅作为工作进程运行
============================================================
```

### 验证要点

1. ✅ 只有一个进程（进程 1）成功获取锁
2. ✅ 其他进程（进程 2 和 3）无法获取锁，抛出 `BlockingIOError`
3. ✅ 只有获取锁的进程运行调度器
4. ✅ 未获取锁的进程跳过调度器初始化
5. ✅ 锁在进程完成后正确释放

测试脚本会自动清理测试锁文件，无需手动操作。
